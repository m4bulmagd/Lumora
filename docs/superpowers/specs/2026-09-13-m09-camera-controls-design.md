## Camera facts and writes

Use `camera::ControlAccess { Unavailable, ReadOnly, WritableStopped, WritableStreaming }`. Replace `NumericCapability::writableWhileStreaming` with `access` in the same aggregate position. Add defaulted `access` to `RegionOfInterestCapability`, and append `pixelFormatAccess`, `exposureModeAccess`, `gainModeAccess` to `CameraCapabilities`. Defaults are WritableStopped for existing in-memory construction; persisted access authority is explicitly versioned. Independent mode/value permissions support manual-only devices with fixed mode and writable value. All seven access values are validated and fingerprinted. Unsupported enum values are malformed facts.

ExposureConfiguration/GainConfiguration mode becomes optional. Fully absent exposure/gain has no modes, unavailable mode and value access, null mode/value, and canonical numeric range 0/0/0. An available Auto-only mode can have unavailable numeric adjustment and null value. Available Manual requires a readable numeric range and value. Pixel format and ROI remain valid required frame facts even when their controls are unavailable; FPS ranges/readback remain finite positive pacing facts even when adjustment is unavailable. Unavailable controls never authorize node writes.

Add pure virtual `ICameraDevice::readConfiguration() -> Result<CameraConfiguration>`. It runs on the acquisition thread after capabilities on connect and again immediately before Apply. Publish `CameraStatusSnapshot::currentConfiguration` separately from applied configuration; a read cannot grant applied/confirmed revisions, restore eligibility or Start. Cleanup clears it. Valid readback requires positive actual FPS, valid frame facts and supported optional exposure/gain. Auto readback may include a readable measured numeric value; Auto requests keep that value null. Rollback canonicalizes the request accordingly and verifies restored Manual values exactly, while Auto measurements may vary. A malformed read fails closed. Current values never enter the capability fingerprint.

The camera API owns common capability validation and request/readback validation. Add `validateCameraCapabilities`, `validateCameraConfigurationReadback`, and `planCameraConfigurationChange(requested,current,capabilities,bool streaming) -> Result<CameraConfigurationWriteMask>`; the mask has `pixelFormat`, `roi`, `frameRate`, `exposureMode`, `exposureValue`, `gainMode`, `gainValue` booleans. Match fixed fields against fresh actual readback and reject changed fixed/unavailable fields before backend Apply. WritableStreaming permits changes stopped or streaming; WritableStopped only stopped. Existing application editing remains stopped-only. FPS null retains camera-selected semantics only when writable. Manual → Auto clears the numeric request without writing the numeric node; Auto → Manual with a fixed numeric value cannot fabricate that value and is rejected if it is not in current readback. Backends plan again against their own actual facts and write only permitted changed nodes, including rollback. The simulator preserves fault consumption atomicity and truthful quantized readback.

The simulator initializes actual configuration explicitly, exposes readback, and preserves fixed values during other edits. Replay format is read-only; its ROI access is deliberately preserved when deriving dimensions. Existing simulated exposure/gain controls model register/readback values, not brightness or auto algorithms; production composition remains manual-only and documents that distinction.
