## Global Constraints

- Keep every device retrieve call bounded at 250 ms. Stop/Disconnect retain the existing 500 ms controlled completion allowance; Shutdown remains cancellable.
- A terminal acquisition timeout requires exact Acquisition/acquisition_timeout classification and no accepted frame for at least max(750 ms, three applied-actual frame periods). Timeout counters are diagnostics, not elapsed time.
- Arm timing only after successful Start; renew only on valid accepted frames; disarm on Stop/cleanup. Repeated Start while already Streaming must not renew it. Historical lastAcquiredAt stays honest.
- Use the latest applied actual FPS, which must be positive and finite. Avoid overflowing duration conversions for tiny positive rates or extreme clock epochs.
- Quick timeout returns are padded only to the end of the same real 250 ms retrieval slice, with cancellation. Do not add a whole extra sleep to slow retrieval or pace unrelated drop types.
- Preserve exact source descriptor, full ROI, continuous acquisition mode, context/pools/generation/source sequence, selection/revision guards, fresh confirmation and manual Retry. No source rebind or new public presenter/controller API.
- FPS must be explicitly present, positive and finite for live admission. The numeric editor uses capability bounds/increment, preserves off-increment requested values and shows actual readback separately. No Auto FPS or capability/schema extension.
- If the advertised FPS range is finer than Qt's numeric editor can faithfully represent, disable FPS editing and Apply with an explanation. Do not silently round bounds or impose the simulator's 1 FPS minimum on other capabilities.
- Saved requested/actual equality remains exact; new unconfirmed requests cannot bypass review through Resume.
- Preserve unrelated edits in the root checkout and ignored QA evidence. Do not imply hosted CI completes native Windows 11 validation.
