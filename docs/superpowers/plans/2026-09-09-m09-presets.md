# M9 Presets and Typed Persistence Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Complete the approved M9 Task1 preset domain, resource and typed persistence without changing live UI/startup behavior.
**Architecture:** Qt-free application preset state/repository validates through processing; configuration adapters load resources, decode entries and migrate the existing atomic store to schema3.
**Tech Stack:** C++20, existing Qt6 Core JSON/resources, PipelineCompiler, GoogleTest/CTest and CMake.
**Spec:** `docs/architecture/milestones/m09-presets.md`, refining M9 Task1 and design §§11.3/13.

## Global Constraints

- UI code never calls a camera device or processing stage directly.
- Original, Enhanced, and Compare are presentation modes, not pipeline mutations.
- Built-in presets are neutral, immutable, and never claim clinical validation.
- Manual parameter edits select Custom and publish one complete valid pipeline revision.
- Reset changes processing only.
- Record UI is absent from all v1 production and evaluation compositions.
- Task1 implements repository state only; live publication/UI belongs to Task2. Application remains Qt-free, and camera/startup/processing hot paths remain unchanged.
- Presets preserve fixed eight-stage order, numeric sensor precision, no camera/orientation data, existing Standard values and separate acceptance gates.

### Task 1: Validated preset domain and state

**Files:** Create application/include/lumora/application/{Preset.hpp,PresetRepository.hpp}, application/src/PresetRepository.cpp, tests/unit/application/PresetRepositoryTests.cpp. Register only these in src/CMakeLists.txt and tests/CMakeLists.txt.

**Interfaces:**
```cpp
struct PresetId { std::string value; bool operator==(const PresetId&) const = default; };
struct Preset {
    PresetId id;
    std::string name;
    std::string description;
    bool builtIn{false};
    std::uint32_t schemaVersion{1};
    std::uint64_t revision{1};
    processing::PipelineDefinition pipeline{processing::defaultPipeline()};
};
struct PresetState {
    std::vector<Preset> customPresets;
    PresetId selectedId{"original"};
    processing::PipelineDefinition activePipeline{processing::defaultPipeline()};
};
core::Result<void> validatePresetPipeline(const processing::PipelineDefinition&);
core::Result<void> validateCustomPreset(const Preset&);
class PresetRepository {
public:
    static core::Result<PresetRepository> create(std::vector<Preset> shipped,
                                                PresetState state = {});
    std::vector<Preset> list() const;
    core::Result<Preset> find(const PresetId&) const;
    core::Result<processing::PipelineDefinition> apply(const PresetId&);
    core::Result<void> edit(processing::PipelineDefinition);
    core::Result<PresetId> classify(const processing::PipelineDefinition&) const;
    core::Result<void> saveCustom(PresetId, std::string name, std::string description);
    core::Result<void> deleteCustom(const PresetId&);
    core::Result<void> restore(PresetState);
    PresetState snapshot() const;
};
```
Result failures are Configuration-category typed core::Error. IDs and names must be nonempty (whitespace-only invalid); custom description may be empty. Existing user IDs update their recipe; reserved IDs cannot. Candidate allocations/validation complete before state mutation. No public mutable references or raw borrowed preset handles.

### Task 2: Resource, codec and migration

**Files:** Create config/default-presets.json; configuration/include/lumora/configuration/PresetCodec.hpp; configuration/src/PresetCodec.cpp and PipelineDefinitionCodec.hpp/.cpp (private helpers); configuration/resources/default-presets.qrc; tests/unit/configuration/PresetCodecTests.cpp. Modify ApplicationConfiguration.hpp, ConfigurationCodec.cpp, ConfigurationStore.cpp, .gitignore (allow only the shipped default JSON), existing ConfigurationStoreTests/StartupPreferencesTests, and configuration/resource/test CMake registration.

**Interfaces:**
```cpp
struct PresetIssue {
    std::optional<std::size_t> entryIndex;
    std::optional<application::PresetId> presetId;
    core::Error error;
};
struct DecodedPresetState {
    application::PresetState state;
    QJsonObject legacy;
    std::vector<PresetIssue> issues;
};
class PresetCodec {
public:
    static core::Result<application::PresetRepository> loadDefaultRepository();
    static core::Result<DecodedPresetState> decode(const QJsonObject&);
    static core::Result<QJsonObject> encode(const application::PresetState&,
                                           const QJsonObject& legacy = {});
};
```
ApplicationConfiguration.presets is application::PresetState; legacyPresets is QJsonObject; presetIssues is vector<PresetIssue> load-only metadata; CurrentSchemaVersion is3. PresetIssue may live in its own small configuration header to avoid include cycles. Serializer paths remain Qt-only. PipelineDefinitionCodec is private to configuration; do not export unnecessary APIs.

- [ ] Write codec/resource tests first and capture RED. Use literal JSON/parameter expectations as well as round trips; preserve existing startup/store behavior tests while replacing raw preset fixture fields with valid typed state.
- [ ] Embed complete five-entry JSON resource. Use correct static-library Qt resource initialization and prove loading works after changing CWD. Resource/parser failures return typed errors. Resource initialization failures must propagate without quarantining valid user configuration.
- [ ] Implement strict stage/parameter/version types with finite numeric checks. Preserve exact uint64 recipe revision using a decimal string; never route it through JSON double. Runtime pipeline revision is omitted/reset0. Reject lossy UTF-8 conversion at the JSON boundary. Reject missing/unknown/reordered stage data.
- [ ] Implement first-valid-entry recovery and indexed warnings. Recover valid active values to Custom for invalid selection; invalid active values recover to Original with warning. Encode validates full state strictly and never silently drops an invalid in-memory entry.
- [ ] Migrate explicit1->2->3, retaining old opaque presets under legacy and unrelated sections/startup. Schema3 decode uses typed codec; schema3 encode emits only validated state and preserved legacy metadata. Whole-envelope failures keep existing quarantine/default semantics. Successful recovery/migration sets a summary loadWarning in addition to detailed presetIssues, with usedDefaults=false so startup persistence remains usable.
- [ ] Test encode failure leaves the old file untouched; schema1 migration equals explicit schema2 and normalized schema3; startup save/load preserves preset state and issues are not serialized. Run focused Debug/Release tests, self-review, report evidence.
