# M9 Task 3 synchronized display modes implementation plan

> **For agentic workers:** Use superpowers:subagent-driven-development for bounded renderer and presenter/UI tasks. Root owns shared builds, Git, final evidence and integration.

**Goal:** Let the operator switch between Original, Enhanced and synchronized side-by-side Compare, including on the frozen paused bundle.

**Architecture:** Extend the existing ImageViewport into one canvas with one paint transaction and one ViewportTransform. FramePresenter retains the pending/completed bundle authority and matches a token-bearing paint receipt before publishing displayed state. WorkstationView exposes mode intents and availability without acquiring frames or controlling processing.

**Tech stack:** C++20, Qt Widgets/QPainter, existing pinned CMake/vcpkg Linux and Windows simulator presets.

**Spec:** [M9 Task 3](2026-04-25-m09-presets-workstation-ui.md#task-3-original-enhanced-and-synchronized-compare-presentation) and [architecture sections 5, 7, 10.3 and 11.2](../specs/2026-04-25-xray-imaging-workstation-design.md).

## Scope and decisions

The owner authorized Task 2 publication/merge after both CI platforms pass and continuation with Task 3. The Compare worktree starts from Task 2 publication head `bf21cee`; integrate the successful Task 2 merge before feature finalization. Camera dialogs, fullscreen, custom recipe save/delete UI and capture remain subsequent work. No processing algorithm, source format, installation orientation, resource pool or performance target changes.

The older plan listed a separate ComparisonViewport widget. The current ImageViewport already owns validated Gray8 wrappers, paint completion, pending/completed state, input and transforms. Extend it directly and test its comparison behavior in ComparisonViewportTests; a second widget would duplicate ownership and input logic. The public standalone `present(frame)` and existing accessor remain compatible.

Compare has equal left/right drawable widths with a centered, non-draggable 1–2 logical-pixel divider (the remainder after equal integer halves). One transform is computed for the half bounds and offset into each side. Installation orientation is already baked into both display planes and must never be reapplied. Fit uses the pane dimensions; manual zoom preserves source center/scale subject to existing clamps. Right-side wheel coordinates are translated to pane-local coordinates; drag deltas and Fit/100%/zoom controls update both planes.

Availability follows the newest admitted live bundle, or the completed frozen bundle while paused. A live bundle without Enhanced selects Original and disables Enhanced/Compare with a visible reason. Recovery enables the choices without overriding Original automatically. Before any image all mode actions are disabled. A paused Enhanced/Compare view remains available when the frozen bundle has both planes, even if processing later fails. Resume reevaluates the newest bundle.

## Shared interfaces

New `src/ui/include/lumora/ui/DisplayMode.hpp` defines `enum class DisplayMode { Original, Enhanced, Compare };`.

ImageViewport.hpp adds a value presentation and a distinct completion observer:

```cpp
struct ViewportPresentation final {
    std::uint64_t token{0U};
    DisplayMode mode{DisplayMode::Original};
    std::shared_ptr<const core::DisplayFrame> originalDisplay;
    std::shared_ptr<const core::DisplayFrame> enhancedDisplay;
};
using CompletionObserver = std::function<void(const ViewportPresentation&)>;
core::Result<void> present(ViewportPresentation presentation);
void setCompletionObserver(CompletionObserver observer);
```

The struct is in `lumora::ui`; the alias and methods are ImageViewport members. The old `present(shared_ptr<DisplayFrame>)` delegates to a token-zero Original presentation. The old frame-only observer setter adapts to the same single internal completion observer; setter names are distinct so clearing with `{}` is unambiguous. All existing transform, clear and discard APIs stay intact.

Pair submissions require Original; Enhanced/Compare additionally require Enhanced. When Enhanced is supplied, validate identical source IDs, dimensions, installation orientation and DisplayMapping (including revision), even for Original selection. Return typed InvalidFrame errors, including `comparison_frame_mismatch` for different IDs, without altering pending/completed state. Prepare every selected QImage wrapper before replacing pending state or resizing the transform. Receipt owners/token/mode exactly describe the completed draw, and one receipt fires after the entire selected presentation is painted. Zero-size/unpainted canvases cannot acknowledge. Compare paints translated Original/Enhanced labels above each plane; single-mode labels remain in WorkstationView.

WorkstationView adds:

```cpp
void setDisplayModeAvailability(bool hasImage, bool hasEnhanced);
void setPresentedDisplayMode(DisplayMode mode);
// signal
void displayModeRequested(lumora::ui::DisplayMode mode);
```

Keep `setPreviewSource(bool)` as a compatibility adapter. Three exclusive QAction-backed buttons (`originalModeAction`, `enhancedModeAction`, `compareModeAction`) emit intents. Availability controls enabled states and an operator-readable reason. Checked state, preview label and canvas accessibility identify the completed painted mode. The central evaluation/paused/stale/waiting overlays remain above the whole canvas, and existing viewer shortcuts remain scoped to the viewport.

FramePresenter adds `void setDisplayMode(DisplayMode mode)` and `DisplayMode displayMode() const noexcept` (completed mode when an image exists). It owns requested mode, monotonically increasing presentation tokens, pending bundle/mode/token and completed mode. Default desired mode is Enhanced, preserving Task 2 until an unavailable bundle falls back to Original. Selection while live resubmits the pending bundle if present, otherwise completed; selection while paused uses only completed. The receipt must match token, mode and exact frame owners. Only a newly completed source bundle increments displayedFrameCount and sets completedAt. Mode-only repaint preserves frame timestamp, age, frame count and stale deadline. Pause discards all pending pixels/mode, restores completed mode/availability, and freezes the completed presentation bundle while acquisition continues. ResetSource clears both planes, pending/completed tokens and mode availability; no old receipt can complete a new session. Reset never issues acquisition or processing commands. An unavailable direct setDisplayMode request is ignored without changing desired mode, pending/completed ownership, or paint state; no invalid viewport submission is issued. Destruction disconnects the mode intent and clears the completion observer before presenter state is destroyed, preserving the existing safe post-destruction paint behavior.
